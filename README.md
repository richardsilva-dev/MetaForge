# MetaForge

**A safety-first laboratory for evolutionary algorithm research and meta-engineering.**

MetaForge runs bounded experiments over algorithm candidates. It generates candidate descriptors, applies a mandatory safety review, executes only trusted allow-listed implementations, verifies correctness against an independent oracle, measures performance, selects candidates, and records their lineage.

> **Current scope:** Python integer sorting with a fixed set of trusted implementations. MetaForge does not execute arbitrary source code generated by an AI agent. A subprocess is fault containment, not a hardened sandbox.

## Current capabilities

- Deterministic specialist-agent contracts, registry, and workflow.
- Candidate Designer, mandatory Candidate Safety Reviewer, and Benchmark Analyst.
- Optional LangGraph adapter (the orchestration extra); the core does not require an LLM or orchestration framework.
- Built-in sort, insertion sort, merge sort, heapsort, shellsort, quicksort, and hybrid quicksort variants.
- Seeded population generation, mutation, crossover, Pareto/crowding selection, strategy diversity preservation, and candidate lineage.
- Multi-objective ranking across median runtime and traced Python allocation peak, with raw repeat samples and median absolute deviation.
- Correctness gate against Python's independent sorted() oracle.
- Repeated timing and traced Python-memory measurements.
- Bounded parallelism, evaluation budget, worker timeout, and global experiment deadline.
- Dataset SHA-256, run identifier, UTC timestamps, environment metadata, configuration, and immutable JSON archives.
- Deterministic candidate-sequence replay from archived synthetic CLI datasets.
- Markdown reports with provenance and lineage.

## Architecture

    Problem + dataset
          |
    Candidate Designer
          |
    Candidate descriptors -> Safety Reviewer (mandatory)
          |
    Bounded evaluation scheduler
          |
    Worker process -> trusted allow-listed algorithm
          |
    Correctness oracle -> reject incorrect candidates
          |
    Repeated benchmark -> Analyst -> selection -> mutation
          |
    Lineage + environment + dataset hash
          |
    Immutable JSON archive + Markdown report

Agent output is untrusted input. Agents can propose or summarize; only deterministic code decides whether a candidate passes safety and correctness gates.

## Requirements and installation

- Python 3.11+
- pytest for development

    python -m venv .venv
    # Windows PowerShell: .venv\\Scripts\\Activate.ps1
    # Linux/macOS: source .venv/bin/activate
    python -m pip install -e ".[dev]"

Optional LangGraph integration:

    python -m pip install -e ".[dev,orchestration]"

## Run an experiment

    python -m metaforge.cli run --size 200 --generations 3 --seed 7 --repeats 3 --population-size 15 --max-evaluations 64 --max-workers 2 --global-timeout 120

The CLI writes:
- .artifacts/latest.json and .artifacts/latest.md as convenient latest-run pointers.
- .artifacts/runs/<run_id>.json and .artifacts/runs/<run_id>.md as immutable run archives.

The CLI's synthetic dataset is embedded in its run artifact so the experiment can be replayed. Do not put confidential or personal data in experiment artifacts.

## Replay a run

    python -m metaforge.cli replay --run .artifacts/runs/<run_id>.json

Replay verifies the embedded dataset hash and repeats the same candidate-generation/evaluation sequence. Timing values are not expected to match because machine load, CPU frequency, Python runtime, and operating-system scheduling vary. The report states whether the candidate fingerprint/validity sequence matches.

## Tests

    python -m pytest

CI covers Python 3.11, 3.12, and 3.13, executes a CLI smoke test, and separately installs LangGraph to test the optional adapter.

## Security boundary

The worker process inherits the host user's operating-system permissions. Output size is checked after capture and therefore is not a hard memory limit. V0.2 does not provide OS-level CPU/memory isolation. Never use this runner for hostile or untrusted source code.

Before enabling agent-generated code execution, implement and independently test a fail-closed OS/container sandbox: unprivileged identity, isolated minimal filesystem, disabled network, CPU/memory/process/file limits, bounded logs, syscall restrictions where available, and reliable teardown. Credentials, home directories, SSH keys, cloud tokens, and host sockets must never be exposed.

## Roadmap

- **V0.1:** controlled experiment loop and correctness gate.
- **V0.2 (released):** specialist-agent contracts, mandatory safety review, bounded scheduling, provenance, lineage, and replay.
- **V0.3 (in progress):** expanded algorithm families, crossover, mutation, Pareto selection, and diversity preservation.

- **V0.4:** external agent-runtime adapters and optional LLM-based proposals behind strict schemas and deterministic gates.
- **V0.5:** C/Rust backend interfaces with separate compilation/runtime measurement.
- **V0.6:** hardened sandbox, fuzzing, and sanitizers.
- **V1.0:** extensible multi-problem research laboratory.

Benchmark values are exploratory. Do not claim general performance improvements without controlled, repeated comparisons across representative datasets and hardware.
