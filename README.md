# MetaForge

**A safety-first experimental laboratory for evolutionary algorithm search.**

MetaForge explores bounded algorithm variants through a repeatable loop: generate candidates, execute trusted implementations in worker processes, verify correctness, measure resource use, select valid candidates, and create new generations.

> **V0.1 scope:** controlled integer sorting with a fixed allow-list of trusted Python implementations. This release does not execute arbitrary source generated by an AI agent. A subprocess is not a hardened sandbox.

## Capabilities

- Declarative candidate descriptors with strict allow-list validation.
- Built-in sort, insertion sort, merge sort, and three-way quicksort variants.
- Seeded population generation and mutation.
- Worker-process execution with timeout, input/output limits, and metrics.
- Correctness gate against Python's sorted() oracle.
- Repeated measurements, median runtime, and traced peak Python memory.
- Elitist selection, JSON experiment history, and Markdown reports.

## Architecture

```text
Problem + dataset
      |
Candidate generator -> allow-listed candidate descriptors
      |
Evolution engine -> worker process -> trusted algorithm
      |                    |
Correctness gate <- result + metrics
      |
Benchmark -> selection -> mutation -> next generation
      |
JSON lineage + Markdown report
```

## Requirements

- Python 3.11+
- pytest for development

## Install

```bash
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -e ".[dev]"
```

## Run

```bash
python -m metaforge.cli run --size 200 --generations 3 --seed 7 --max-evaluations 64 --max-workers 2 --global-timeout 120
```

Outputs are written to `.artifacts/latest.json` and `.artifacts/latest.md`.

## Test

```bash
python -m pytest
```

## Specialist agents (V0.2 in progress)\n\nThe current agent layer defines typed task/result contracts and an explicit registry. The built-in Candidate Designer proposes bounded candidate populations, the Safety Reviewer checks candidate descriptors against the static allow-list, and the Benchmark Analyst summarizes measured results. The evolution engine invokes these roles. These are deterministic reference agents, not LLM agents. External runtimes can be integrated through adapters; agent outputs remain untrusted and cannot override deterministic correctness or security gates. See [agent framework selection](docs/agent-framework-selection.md).\n\n## Security boundary

Candidate descriptors are data, not source code. V0.1 only dispatches to trusted implementations shipped with the package. The worker inherits the host user's operating-system permissions; it is not safe for hostile code. Before executing agent-generated code, MetaForge must add a fail-closed OS/container sandbox with an unprivileged identity, minimal filesystem, disabled network, CPU/memory/process/file limits, and reliable cleanup. Never expose credentials or host sockets.

## Roadmap

- **V0.1:** controlled experiment loop and correctness gate.
- **V0.2:** specialist-agent interfaces, bounded parallelism, and global budgets.
- **V0.3:** crossover, richer mutations, diversity preservation, multi-objective selection.
- **V0.4:** durable lineage and replay.
- **V0.5:** C/Rust backend interfaces.
- **V0.6:** hardened sandbox, fuzzing, sanitizers.
- **V1.0:** extensible multi-problem research laboratory.

Benchmark results are exploratory. Do not claim general performance improvements without controlled, repeated comparisons across datasets and hardware.
