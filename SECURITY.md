# Security Policy and Threat Model

## Scope

MetaForge accepts AI-proposed Python source only in the source-level integer-sorting experiment. Candidate source is untrusted, even when generated by a configured model. The descriptor optimizer and the trusted C/Rust backends are separate paths; the latter compile repository-owned source only.

## Security controls

The source-level path applies multiple independent controls:

1. Strict structured model output, no agent tools or handoffs, one turn per proposal, bounded call time, global experiment deadline, and a finite call budget.
2. A conservative AST policy that rejects non-allow-listed imports, wildcard imports, direct dynamic execution and common I/O/reflection calls, dunder attribute access, selected filesystem mutation methods, asynchronous functions, classes, defaults, annotations, and oversized syntax trees.
3. Mandatory rootless-container preflight and a trusted smoke probe before model calls.
4. A SHA-256-pinned local image; the runtime does not pull images during candidate execution.
5. No container network, read-only root filesystem, read-only workspace, non-root UID, all Linux capabilities dropped, no-new-privileges, CPU/memory/swap/PID limits, bounded temporary storage, bounded output, file/process limits, and wall-clock timeout.
6. A trusted in-container wrapper that measures only the candidate call, validates result shape, and rejects incorrect results.
7. A second host-side correctness oracle before a candidate can be selected.
8. Immutable run archives with dataset hashes, source fingerprints, and lineage; replay repeats review and sandbox checks without a model call.

## Explicit non-guarantees

- AST review is not a proof that Python code is safe. Python's dynamic object model makes static allow-lists inherently incomplete.
- A rootless container is a defense-in-depth boundary, not a formal proof against container-runtime, kernel, WSL, hypervisor, or host vulnerabilities.
- CPU and memory limits do not eliminate all denial-of-service risks against the host or container daemon.
- Timing measurements may be noisy and do not establish general performance improvements without representative workloads and controlled repeated trials.
- Current model-generated source support is Python-only and restricted to integer sorting. It does not yet generate or apply repository-wide multi-file refactoring patches.
- The C11 and Rust backends execute trusted repository source; they do not accept generated native programs.

## Operational requirements

- Use a disposable VM or dedicated isolated host for high-risk experiments.
- Keep API keys outside experiment containers and never commit keys, tokens, personal data, or private datasets.
- Keep the sandbox image pinned by digest and update it only through reviewed dependency/image changes.
- Do not disable rootless mode, no-network enforcement, cgroups, read-only mounts, or other sandbox controls to make a failing test pass.
- Treat any sandbox preflight or smoke failure as a hard stop: no model proposal or candidate execution should occur.

## Reporting

Report suspected vulnerabilities privately to the repository owner. Include the affected commit, minimal reproduction, impact, and environment details. Do not publish exploit payloads for an unpatched issue.
